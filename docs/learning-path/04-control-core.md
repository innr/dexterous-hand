# S4 — LEAP 控制软件架构与安全决策

**入口**：S3 PASSED。**目标**：独立设计、实现、解释并验证 LEAP 16 关节控制核心的职责、时序和故障行为。
**历史资料**：此前讨论的 “LEAP Control Core v0.1” 是架构草案/预习；未在本阶段通过前，不宣称工程已完成或硬件安全。

## 理论与接口
- `RobotRuntime` 拥有 `ControlWorker`、`BusWorker`、`SafetySupervisor`、`StopGate`、`IBus`，定义初始化/退出顺序。
- 通信线程独占 STS3215 串口；控制线程 100 Hz、只读反馈快照、输出目标；ROS2 只提出目标、reset/enable 请求。
- 每关节记录 `received_at` 与 `valid`；设备内部采样时间未知时不把主机接收时间伪装成真实采样时间。
- `SafetySupervisor` 单一状态决策者：NORMAL / DEGRADED / SAFE_STOP / FAULT；外部快速 stop latch **只能置位**，恢复必须授权并重验条件。
- `StopGate` 维护停止请求版本、控制 generation、已准入 / 在途 TX 和授权条件；说明停止请求、准入关闭、TX 清空、物理停止四个不同的边界。
- 正常接触 != 危险接触。负载 / 跟踪误差 / 速度突变只能提供接触线索，初版不宣称物理接触力测量精度。
- 任何安全主张明确范围：本项目教学测试不是功能安全认证；单纯串口停止命令、软件状态变化或断电都不保证机械安全。

## 交付
设计文档（接口、线程图、事件顺序、互斥/atomic 规则、故障表、状态转移表、恢复条件）+ `MockBus` + 核心模块 + 测试报告。模块之间使用依赖注入，能够不用真机完成全流程。

## 验收测试
- S4-T01：正常启动、自检、重新建 generation 后允许合法指令。
- S4-T02：单关节反馈超出软阈值 DEGRADED、超出硬阈值 SAFE_STOP；阈值为配置与测试参数，不冒充真实硬件标准。
- S4-T03：故障解除不自动恢复旧轨迹；reset 和 enable 分开，FAULT 锁存。
- S4-T04：停止与恢复并发交错，新的 stop 请求不会被过期 reset 覆盖；包含停止版本/CAS 测试。
- S4-T05：停止在 beginTx 前/后两个交错点执行；门禁线性化语义成立；旧代次不得重新准入。
- S4-T06：100 ms 模拟串口阻塞时，控制线程不等待总线 I/O；若在途发送无法取消，报告明确未确认状态。
- S4-T07：危险接触、非法目标、限位、CRC/超时、重复命令、异常析构逐一故障注入。
- S4-T08：终止后 worker 已 join，再释放 `IBus`；ThreadSanitizer 可用时无竞争。
- S4-T09：输出停止事件的时间线日志：requested / admission closed / tx drained / actuator safe (mock 仅模拟) 不得混淆。
- S4-T10：运行至少 10k 次随机可复现事件序列，状态不变量保持：FAULT 不自动恢复，stop latch 有效时不允许新普通 TX 准入。

## 通过标准
以上全部通过、带 seed 的失败复现、设计审查记录、接口契约、CI 结果；本人独立解释线性化点与不能证明的硬件行为。通过 S4 **不代表**真机安全达标。
